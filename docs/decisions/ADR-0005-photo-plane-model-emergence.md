# ADR-0005：模型从参考照片平面展开

> 日期：2026-07-29
> 状态：`SUPERSEDED_BY_ADR-0006`
> 历史用途：原“真实照片—模型”过渡方式；静态地面方案不再自动播放 `photo_emerge`。

## 背景

物理空间中始终存在红白手绘触发图。识别后又要展示绘制触发图所依据的真实照片。如果随后把传统独立模型连同厚展台直接摆在识别图中央，会形成三次互不相关的视觉切换：手绘图、平面照片、悬空模型，用户难以理解模型从哪里出现。

九张触发图都是 1:1，但真实照片同时包含横幅、竖幅和不同裁切，且部分照片没有拍到主体地面。因此不能假定所有模型都有完整地基，也不能用同一种厚方台掩盖问题。

## 决策

统一使用“照片卡—浅浮雕—完整三维”的展开方式：

1. 真实照片制作成不拉伸、不裁主体的 1:1 `contain` 图片卡，位置和大小与触发图完全重合。
2. 参考照片卡出现后保持可见，作为模型底部的环境和地面联系。
3. 模型最低点归一到本地 `Y=0`，轴心位于底部中心。
4. 模型在照片中的主体下缘落点由 `subject_anchor_uv` 指定；看不到地面时锚在照片下边缘。
5. 每个 GLB 内置一段无骨骼变换动画 `photo_emerge`：模型由很薄的浅浮雕比例展开为完整三维，底部不移动。
6. 建筑台阶、城墙、雕塑基座等主体构件保留；不添加通用厚展台和不透明大地板。
7. 真实照片的公开展示许可、隐私裁切和水印问题仍是发布前置条件。内部 QA 可以生成派生图片卡，但统一放在忽略目录 `.build/`，不得误作公开交付。

## 原因

- 模型的出现位置与真实照片主体直接对应，减少从二维到三维的跳变；
- 照片继续承担树木、道路和现场环境，不必把这些背景建进模型；
- 根节点变换动画不增加骨骼、Morph、贴图或材质，移动端成本很低；
- 轴心锁在底部，展开过程中不会悬空；
- 一个统一机制可以覆盖建筑、雕塑和天线，同时允许每张照片使用独立锚点。

## 平台交接

- 参数入口：`lkivivube_delivery/source/presentation_profiles.json`；
- GLB 动画名：`photo_emerge`，场景开始时自动播放；
- 参考照片卡长边：识别图长边的 `1.0`；
- 参考照片卡高度：`0.002 × 识别图长边`；
- 模型底部高度：`0.006 × 识别图长边`；
- 模型宽度和 X/Z 位置按每个资产的 profile 填写；
- Kivicube 场景结构列表顺序不决定真实遮挡关系，应在 3D 画布和网页/微信小程序真机中检查照片平面是否正确遮挡展开初期的模型。
